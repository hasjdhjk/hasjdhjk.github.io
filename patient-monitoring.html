A complete monitoring workflow

The system brings simulated physiological signals, patient management, alerting and historical summaries into a desktop application. A separate backend handles accounts and persistent data.

My contribution: I carried out most of the project development, including clinician registration and login and the design and integration of the server-side doctor database, connecting account workflows to the API and persistent storage.

Client–server architecture

  • A Java Swing desktop client communicates with a Java servlet backend through JSON REST endpoints.
  • DAO classes and JDBC connect the backend to PostgreSQL. The service and database are deployed through Tsuru.
  • Gradle supports the build and JUnit supports testing, with a GitHub Actions deployment workflow.

Application capabilities

  • Simulated ECG, respiration and other vital signs, with configurable display windows.
  • Visual and audio alerts for abnormal readings, alert review and minute-averaged history.
  • Patient registration, multi-patient navigation and report export.
  • An HTML/JavaScript Digital Twin view integrated with the Java application.

The final report records passing JUnit tests for core services, including session management, alerts and averaging.

Project scope

This is an educational prototype using simulated physiological data. It is not presented as a clinically validated or production-ready patient-monitoring platform. The patient overview uses demonstration accounts and simulated readings.
